AGENTE COMPRAS IA — BUILD 1.0 RC15 CONFERÊNCIA DE DOCUMENTOS EXTERNOS

Correção principal:
O módulo de conferência documental foi corrigido para NÃO usar documentos gerados pelo próprio sistema como prova documental externa.

Problema corrigido:
Arquivos como 02_DFD.docx, 03_ETP.docx, 04_TR.docx, 05_Designacao_Agente_ETP.docx, 06_Designacao_Agente_TR.docx, 07_Designacao_Gestor_Fiscal.docx, 08_Disponibilidade_Orcamentaria.docx e 09_Certificacao_TR_Padronizado.docx não podem ser usados para comprovar:
- exclusividade;
- consagração;
- justificativa de preço;
- designação de agente;
- gestor/fiscal;
- regularidade jurídica/fiscal;
- proposta comercial;
- certidões.

Regra nova:
1. Documentos gerados pelo sistema são identificados como "peças internas geradas".
2. Documentos externos são analisados separadamente.
3. A completude externa passa a considerar apenas documentos realmente enviados pelo fornecedor/processo.
4. Se o usuário reenviar o ZIP do processo gerado pelo próprio sistema, ele não será contado como documentação externa válida.
5. A interface agora mostra aviso quando arquivos internos forem ignorados na conferência externa.

Mantidas as melhorias anteriores:
- Processo completo DOCX + PDF.
- Modelos oficiais.
- Formatação corrigida.
- Assinaturas dinâmicas.
- Extração da Requisição.
- Dotação e pagamento.

BUILD 1.0 RC28 — Base de Conhecimento Homologada

Implementação:
- Criado módulo de Base de Conhecimento Homologada.
- O sistema NÃO aprende automaticamente com qualquer processo gerado.
- Após revisar um processo, o usuário pode clicar em:
  "Adicionar último processo à Base Homologada".
- O caso homologado é salvo em:
  base_conhecimento/homologada/casos_homologados.jsonl
  base_conhecimento/homologada/documentos/
- Em novos processos, o sistema busca casos semelhantes e informa quando há referência homologada compatível.
- A referência homologada é usada como apoio técnico controlado, sem copiar automaticamente dados variáveis como valor, data, artista, processo ou dotação.
- O módulo evita repetição de erros porque somente processos aprovados manualmente entram na base.

Regra de segurança:
- Não homologar processo antes de revisão humana.
- Processos com erro de texto, data, valor, artista, gestor/fiscal, dotação ou PDF não devem ser adicionados à Base Homologada.
